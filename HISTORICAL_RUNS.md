proof of optimality. These were runs with the original total-spread objective;
they do not establish how long the new fairness objective needs.

## Recovered 18-player warm-start file (2026-10-02)

The history explicitly records v1.1 with `--n 18 --time_limit 6000
--input_csv solution_n18_sol.csv --maximize_spread --seed 73`.
In this project, the recovered file is `solutions/solution_n18_sol.csv`;
there is no copy named `solution_n18_sol.csv` at the project root.
It is byte-identical to `solutions/opt_solution_n18_sol.csv`.

The recovered schedule passes coverage, pair uniqueness, group sizes, and
four-player participation balance checks. Its total spread is 66, minimum
individual spread 2, and worst hogging 0.75. Forcing all its assignments into
the current model is feasible; solving that fixed-assignment model does not
prove the schedule optimal among other schedules.

```sh
.venv/bin/python cp_sat_caseB_v1_1.py --n 18 --time_limit 6000 --maximize_spread --seed 73 --input_csv solutions/solution_n18_sol.csv --out_prefix solutions/n18_warm_trial
```

The prior 3,600- and 21,600-second comparisons had no warm start and used
seed 1. A controlled comparison should keep the seed, workers, time limit,
solver version, and objective fixed while varying only the hint.

`--input_csv` supplies optional search hints; it does not change the feasible
schedules or resume saved solver state. The first-round grouping is still
fixed by the model. Current hint loading supplies only 282 of the 360 player
assignment variables for this CSV: each row stops at its largest player ID.
Completing that loader is a separate possible improvement; these findings
describe the existing version without modifying it.

## Hint replication test (2026-10-02)

A 60-second original-spread run with the recovered hint, seed 73, and eight
workers found spread 66 at 0.13 seconds. It ended FEASIBLE, not OPTIMAL,

replicates the saved schedule quickly but does not establish its optimality.

## Recovered best record from November 2025

`runs/historical_20251120/best_record_001.txt` preserves the original record.
It records best spread 66 using perturbation hint 002 and seed 1. The writer
in checkpoint_runner_v4 logs improvements to the best objective seen; it
does not require OPTIMAL status. Its record timestamp uses UTC, while
the run timestamp uses local time, so their clock readings are not directly
comparable. Two subsequent 90-second runs using this archived schedule
(seeds 67 and 73, dated 21 November) both report FEASIBLE, objective 66,
and bound 70.
